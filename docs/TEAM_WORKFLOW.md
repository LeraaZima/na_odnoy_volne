# Как работать командой через Git + Codex

Это учебный пример. Один человек создаёт GitHub-репозиторий, остальные получают доступ как collaborators.

## Самый первый запуск Git

Откройте папку проекта в VS Code / Terminal:

```bash
git init
git add .
git commit -m "chore: initial MVP scaffold"
git branch -M main
```

Затем создайте **пустой приватный** репозиторий на GitHub (без автоматического README) и свяжите его по инструкции GitHub, например:

```bash
git remote add origin <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
git push -u origin main
```

Не отправляйте `.env` или реальные пароли. При создании публичного репозитория сначала проверьте отсутствие секретов.

## Ветки по задачам

| --- | --- | --- |

| Антон | `feature/swipe-cards` | Карточки фильмов (после backend API) |

Общий контракт API нужно согласовать перед параллельными изменениями. Каждый работает в своей ветке; после проверки создаёт Pull Request в `main`.

## Как передать задачу Codex

Откройте именно рабочую папку репозитория. В начале каждого задания попросите прочитать `AGENTS.md` и `docs/MVP.md`. Запускайте Codex **в выбранной ветке**, чтобы изменения не конфликтовали с работой других участников. Не давайте сразу четырём агентам менять одни и те же файлы.

## Definition of Done

- Код запускается локально после `docker compose up --build`.
- Старый сценарий работы комнат не сломан.
- Нет реальных API-ключей в Git.
- README обновлён, описана ручная проверка функции.
- Проверены тесты и результат зафиксирован в PR.
