# На одной волне

Учебный MVP для дисциплины «Стартап-экосистемы»: два человека выбирают кино и находят фильмы, которые нравятся обоим. Это не видеосервис и не полный проект ВКР.

Работают гостевые комнаты на двоих, общие фильтры, независимые свайпы, серверное сохранение оценок, Match и общая история. Комната живёт 24 часа. Данные хранятся в PostgreSQL; обновление страницы не сбрасывает прогресс.

## Требования и запуск

Нужны Docker Desktop с Docker Compose, современный Chrome/Firefox/Safari и свободные порты 5173, 3001, 5432. Node.js на компьютере для обычного запуска не нужен. Интернет нужен при первой сборке, импорте TMDB и загрузке постеров; уже импортированный каталог доступен из локальной БД.

После публикации скачайте репозиторий или выполните `git clone <URL-репозитория>`, затем перейдите в его папку. Из корня проекта:

1. Запустите Docker Desktop.
2. Если локального `.env` ещё нет, скопируйте [.env.example](.env.example) в `.env`. **Существующий файл не перезаписывайте.**
   Для новой копии можно выполнить `cp -n .env.example .env` (существующий файл сохраняется). Впишите свой ключ TMDB в редакторе, не в командной строке.
3. Выполните:

```bash
docker compose up --build -d
docker compose ps
curl http://localhost:3001/api/health
```

На новом томе таблицы создаются автоматически, затем backend регистрирует четыре миграции в `schema_migrations`. На существующем томе применяются только новые миграции. Проверка/повторный безопасный запуск:

```bash
docker compose exec -T backend npm run migrate
```

**В новой базе фильмов ещё нет:** выполните импорт из раздела ниже до начала выбора. Данные старого компьютера не переносятся вместе с Git-репозиторием.

Откройте **http://localhost:5173**. Healthcheck должен вернуть `{"status":"ok"}`; backend и db — статус healthy.

Для второго участника используйте другой браузер или приватное окно. Две обычные вкладки одного профиля используют один гостевой токен и не являются двумя участниками. Для телефона в той же сети откройте `http://<IP-компьютера>:5173`; разрешите входящие соединения Docker в настройках macOS.

Остановка без удаления данных:

```bash
docker compose down
```

Не добавляйте флаг удаления volumes. При повторном запуске сохраняются каталог, комнаты, оценки и совпадения. Не меняйте параметры доступа PostgreSQL у существующего тома без отдельной процедуры изменения пароля в БД.

## Локальное окружение и TMDB

Секреты заполняются только в локальном `.env`:

- `TMDB_ACCESS_TOKEN` — API Read Access Token **или** `TMDB_API_KEY` — API Key v3. Достаточно одного; при заполнении обоих используется токен.
- `TMDB_LANGUAGE=ru-RU` — язык данных.
- `TMDB_PAGES=1` — число страниц популярных фильмов, от 1 до 3.
- Параметры PostgreSQL — по образцу, для локальной учебной среды.

Не добавляйте префикс `VITE_` к секретам. Не публикуйте `.env`, вывод `docker compose config`, `docker inspect` или скриншоты настроек с ключами. Все варианты `.env.*` исключены из Git и Docker-контекстов, кроме безопасного примера. Если файл уже был добавлен в Git ранее, одного ignore недостаточно.

После изменения окружения пересоздайте backend и выполните импорт:

```bash
docker compose up -d --force-recreate backend
docker compose exec -T backend npm run sync:tmdb
curl 'http://localhost:3001/api/movies?min_rating=7&limit=5'
curl 'http://localhost:3001/api/movies/genres'
```

Импорт обновляет фильмы по TMDB ID без дублей, сохраняет жанры, основные поля и исходный JSON. В проверенном локальном каталоге 58 фильмов и 19 жанров; новый импорт может изменить состав популярных фильмов. При ошибке импорта уже сохранённые записи остаются. Перед защитой повторный импорт не обязателен.

Постеры загружаются непосредственно с TMDB, не копируются в репозиторий. При недоступности изображения показывается фирменная заглушка; у части фильмов источник не даёт описания. На экранах есть логотип TMDB и уведомление: “This product uses the TMDB API but is not endorsed or certified by TMDB.”

## Демонстрация преподавателю

1. В браузере A введите имя и создайте комнату. В независимом браузере B введите другое имя и код.
2. Убедитесь, что оба видят двух участников. Откройте «К выбору фильмов» в обоих окнах.
3. Создатель задаёт, например, год от 2000 и рейтинг от 6, сохраняет настройки. Второй участник видит их, но не может менять.
4. Создатель нажимает «Начать выбор». Оба видят первый фильм общей колоды.
5. A ставит первому фильму лайк, следующему — дизлайк. B пока остаётся на первом: скорость независима.
6. B ставит первому фильму лайк. На обоих экранах появляется «Вы на одной волне!».
7. Нажмите «Продолжить выбор», откройте «Совпадения» и подробности фильма.
8. Обновите страницы: история и собственный прогресс сохранятся.

Свайпы работают мышью и пальцем; есть кнопки. Клавиатура: Tab до колоды, ←/→ для оценок, Escape для закрытия Match. Доступны светлая/тёмная темы и системное уменьшение движения.

## Проверки

Из корня проекта, после запуска контейнеров:

```bash
docker compose exec -T backend npm test
docker compose exec -T backend env RUN_DB_TESTS=1 npm test
docker compose exec -T frontend npm run build
docker compose exec -T frontend node --input-type=module < frontend/scripts/check-rooms.mjs
```

С `RUN_DB_TESTS=1` выполняются 28 тестов, включая PostgreSQL, реальные фильтры, права, повторные и одновременные запросы, выход/замену участника и истечение срока. Без этой переменной интеграционные тесты пропускаются. Socket.IO-сценарий проверяет polling/WebSocket, синхронизацию, Match и восстановление истории.

Для браузерных проверок на macOS дополнительно нужны Node.js и Google Chrome:

```bash
npm install --prefix /tmp/wave-ui-check --no-audit --no-fund playwright-core
PLAYWRIGHT_MODULE=/tmp/wave-ui-check/node_modules/playwright-core/index.mjs node frontend/scripts/check-voting-ui.mjs
PLAYWRIGHT_MODULE=/tmp/wave-ui-check/node_modules/playwright-core/index.mjs node frontend/scripts/check-demo-ui.mjs
```

Первый сценарий запускает два независимых Chrome, проверяет мышь, touch, клавиатуру, синхронизацию фильтров, Match на обоих экранах, потерю ответа, историю и замену гостя. Второй проверяет 390/1280 px и обе темы, пустую подборку, реальные отсутствующие описания, отказ загрузки постера и истечение комнаты во время отключения сети. Ожидание сетевого таймаута занимает около минуты. Второй скрипт рассчитан на стандартные локальные имя БД и пользователя `wave` и каталог с хотя бы одним фильмом без описания.

Проверки создают собственные комнаты. Backend-тесты и аудит интерфейса удаляют только свои тестовые комнаты; сценарии Socket.IO и двух Chrome удаляют своих участников, оставляя тестовую историю. Не запускайте тесты на чужой рабочей БД. Скриншоты браузерных проверок находятся в `/tmp/wave-*.png`.

### Ручные пограничные проверки

- **Пустая подборка:** оба года 1880 → начать выбор → сообщение и возврат к фильтрам.
- **Повтор:** двойной клик по лайку не должен пропустить следующий фильм или создать второй Match.
- **Сеть:** отключить сеть одного браузера, затем вернуть. Сессия сохраняется; после восстановления история перечитывается. При истёкшей/отозванной сессии интерфейс возвращается на главную.
- **Замена гостя:** второй участник выходит, новый входит по коду. Его оценки пусты, прежняя история доступна; лайки ушедшего не создают новых совпадений.
- **Мобильный экран:** 390 px, обе темы, открытые подробности и Match; кнопки доступны, горизонтальной прокрутки нет.
- **Доступность описаний:** один фильм в двух разных подборках может дать две записи истории. Раскройте обе: каждая кнопка управляет своим описанием.

## Публикация на GitHub

Первоначальный коммит подготовлен локально; отправка выполняется только владельцем после проверки. Создайте пустой репозиторий GitHub без автоматически добавляемых README и лицензии. Проверьте видимость репозитория и согласие команды на публикацию материалов.

```bash
git status
git remote add origin <URL-вашего-репозитория>
git push -u origin main
```

Если `origin` уже существует, сначала проверьте его адрес, не заменяйте вслепую. Для HTTPS используйте авторизацию GitHub, для SSH — настроенный SSH-ключ; не вставляйте токены в URL репозитория. Коммит использует настроенное локально имя и email автора — они будут видны в истории. Не публикуйте Docker-тома, дампы БД и локальное окружение. Лицензия на код пока не выбрана командой; наличие публичного репозитория само по себе не даёт разрешения на произвольное использование.

## Устройство и правила данных

[frontend/src/](frontend/src/) — React, CSS и Socket.IO-клиент; [backend/src/](backend/src/) — Express, PostgreSQL и Socket.IO; [backend/sql/](backend/sql/) — миграции; [backend/test/](backend/test/) — тесты; [docker-compose.yml](docker-compose.yml) — три сервиса.

Docker устанавливает npm-зависимости через `npm ci` по сохранённым lock-файлам. Обновления зависимостей требуют осознанного обновления lock-файлов и повторных проверок.

Новые миграции выполняются автоматически при старте backend, журнал хранит контрольные суммы. **Уже применённые SQL-файлы не редактируйте.** PostgreSQL init scripts работают только на новом томе; обновления существующего тома выполняет мигратор.

Создатель задаёт общие фильтры: любой из выбранных жанров, диапазон годов, минимальный рейтинг, максимальная длительность; остальные ограничения соединяются условием «и». Сессия фиксирует до 200 фильмов по популярности и ID. Новые фильтры заменяют текущую подборку; история старых совпадений остаётся.

Голоса и Match определяются сервером, транзакцией с блокировкой комнаты и уникальными ограничениями. Повтор прежнего голоса безопасен; за следующий фильм до текущего голосовать нельзя. Оценки ушедшего не учитываются при новых совпадениях. Socket.IO уведомляет, PostgreSQL хранит истину. После возврата старые совпадения появляются в истории без повторной анимации.

### Основные API

- `GET /api/movies`: `q`, `genre_id`, `year_from`, `year_to`, `min_rating`, `max_runtime`, `limit` (1–50), `offset`. Поиск только в импортированном каталоге.
- `GET /api/movies/genres`, `GET /api/movies/:tmdbId`.
- `POST /api/rooms` и `POST /api/rooms/:code/join`: `{name}`.
- `GET /api/rooms/:code`, `DELETE /api/rooms/:code/me`.
- `PUT /api/rooms/:code/filters`: `{revision, filters: {genreIds, yearFrom, yearTo, minRating, maxRuntime}}`.
- `POST /api/rooms/:code/selection`: `{revision}`.
- `GET /api/rooms/:code/voting`, `POST /api/rooms/:code/votes`: `{selectionId, movieId, choice: "like" | "dislike"}`.

Чтение/изменение комнаты, оценки и история требуют гостевой Bearer-токен; фильтры и запуск — права создателя. Устаревшая версия/голос за старую подборку получают 409. События: `room:updated`, `votes:updated`, `match:created`.

## Ограничения MVP

Нет отмены голоса, передачи прав создателя, автоматического удаления истёкших комнат и долговременной очереди Socket.IO-уведомлений. Если создатель вышел, готовая колода остаётся, для новых настроек нужна новая комната. История общей комнаты включает совпадения прежней пары с её именами. Настроение, аккаунты, платежи и воспроизведение не реализованы.

Версия рассчитана на локальную защиту, не публичный production: до публикации нужны HTTPS, ограничения частоты запросов и отдельная эксплуатационная подготовка. Проверки Chrome не заменяют отдельное тестирование Safari/iOS и физических устройств.
